# AurAgrid project state

Last verified on the server: 2026-11-19. Read this, then `RESEARCH.md` (the
Phase 1 plan and source licensing) and `deploy/README.md`, before changing anything.

AurAgrid is a small L402 data oracle at **https://84.12.79.124**. It sells two
feeds computed from its own Bitcoin and Lightning nodes and gives away seven
more: delayed or daily copies of the paid two, and five from U.S. public-domain
sources (EIA, NOAA, USGS). Every response carries `provenance` and is signed.
Nothing is simulated: a feed without fresh real data answers 503, and a paid
feed is never charged for while it is stale (see Degraded feeds).

## Rules

1. **The system never moves funds.** No sweeps, no outgoing payments. The old
   `sweep_to_vault.py`, `dynamic_liquidity_sweep.py` and `auragrid_swarm.py` are
   deleted. The crontab is empty: everything runs under systemd
   (`~/start_auragrid_services.sh` is retired and exits immediately).
2. **Only real data with clear redistribution terms** (see `RESEARCH.md` §2).
   No mock, sample or fallback values anywhere.
3. **Spend nothing.** Everything runs on free tiers: OCI Always Free, free EIA
   key, Let's Encrypt IP certificate (no domain).
4. Run Python from the `auragrid_env` conda env:
   `/home/ubuntu/miniconda/envs/auragrid_env/bin/python`.
5. **Secrets are never committed** (all gitignored or outside the repo):
   `gateway.secret`, `attest.macaroon`, `dvm/dvm_key.txt`, `/etc/auragrid/env`
   (`EIA_API_KEY`), `~/.auragrid/admin_password`, `~/.aperture/` (config with the
   gateway secret, `aperture.db` with macaroon root keys, TLS key), `/etc/lego/`.
   Git history was purged of leaked secrets on 2026-10-31 (see Security history);
   scan staged changes before every commit.

## Stale gate (never take payment for stale data)

`jobs.feed_degraded()`: a feed is stale when its newest stored snapshot is older
than its `stale_after` (`jobs.LIMITS`) or there is none. For a paid feed the
pricer then quotes 0 sats, so Aperture issues **no invoice** and passes the
request on, and the backend answers **503** with `stale: true`, the true
`as_of` and the free `sample_url` (also for token holders and bundle paths).
Refusals are counted in `ledger.db` (`counters`, shown on the dashboard). It
reverts automatically when fresh data is stored. Free feeds are served marked
`stale`. The 30-day bundle keeps a static price (Aperture scopes dynamically
priced tokens to one path), so a bundle bought while a feed is stale is not
refused at purchase, only its stale requests. (Before 2026-11-19 stale paid
data was served free instead.)

## HTTPS

renewed automatically; the one installed on 2026-11-08 expires 2026-11-14). `auragrid-cert-renew.service` runs
`/usr/local/bin/lego run` (state in `/etc/lego`, HTTP-01 on :80) and renews at

(root-owned copy of `scripts/install_tls_cert.sh`) installs the certificate as
`~/.aperture/tls.cert` / `tls.key` and restarts Aperture, which only loads
certificates at startup (a few seconds of downtime per renewal).
Check: `systemctl list-timers auragrid-cert-renew.timer`,
`openssl x509 -in ~/.aperture/tls.cert -noout -enddate`.

## Response signing

Every successful `/api/v1/` data response carries `X-AurAgrid-Signature-V2` +
`X-AurAgrid-Timestamp` (clients may send `X-AurAgrid-Nonce` to bind it to their
request), signed by the production LND key
`038041ef6643bb59d9ec73568a952183b261683968cb4000b547302fa464cf8228` through
`attest.macaroon` (`message:write` only; set in `scripts/run_backend.sh`). Scheme
in `attestation.py` (v2; the old path-only v1 is forgeable and no longer
produced). The manifest's `signature` block documents it and `enabled` follows
the setting.

## Known gaps

  `btc-fees` bought end to end with a circular payment from our own node (owner-approved,
  fee cap 2 sats): 9 sats (USD peg at the day's BTC price) out via Amboss.Space and back
  through the 1M channel on a 5-hop route, fee 1.006 sats. The invoice settled, the token
  returned HTTP 200 with fresh data and a valid v2 signature, and the dashboard recorded
  9 sats / 1 token / 1 call under hourly, `btc-fees`. So the dashboard's revenue includes
  9 self-paid sats: subtract them when counting real sales. LND's default pathfinding
  found no route (long route below its minimum success probability); `buildroute` +
  `sendtoroute` did.

- Revenue: 0 settled L402 invoices as of 2026-11-11 (`RESEARCH.md` §1). In the
  7 days to 2026-11-11 the public traffic was ~3,900 scanner requests and 2
  real discovery hits (`/openapi.json`); no real API calls.
- LND on-chain balance is 16,316 sats, below the 30,000 anchor reserve (10k per
  channel) used to fee-bump a force close. Left as is by the owner on 2026-11-11:
  the two income channels (5.3M and 1M inbound) hold none of our funds yet; only
  the 50k Amboss.Space channel (48,032 sats local, all outbound) is exposed.
